## 错误记录

| 错误 | 尝试 | 处理 |
|---|---:|---|
| 官方搜索未直接返回历史会话专题页 | 1 | 改用官方文档入口与本机证据交叉验证 |
| 把 SQLite 点命令与 SQL 放在同一次参数调用导致语法错误 | 1 | 已拆开调用；后续查询使用独立的 `sqlite3 -readonly` 命令 |
| 官方站内搜索未命中 Codex `model_provider` 配置项，猜测的 Markdown 页面也未返回内容 | 1 | 不从未打开页面推断；改用本机扩展协议与数据库做可重复验证 |
| `app-server --strict-config` 因未知字段 `disable_response_storage` 拒绝启动 | 1 | 这是诊断命中而非重复尝试；记录为陈旧配置，普通模式继续验证列表协议 |
| 一次性管道在初始化握手完成前发送列表请求，只返回 initialize 响应 | 1 | 改为保持 PTY 会话，收到初始化响应后再发送 `initialized` 和列表请求 |
| 非 PTY app-server 因标准输入关闭而立即退出 | 1 | 下一次使用可交互 PTY 会话，不重复非 PTY 启动 |
| 移除首个陈旧字段后，严格校验继续发现 `network_access` 也是未知字段 | 1 | 普通运行会忽略；加入候选补丁，继续校验剩余配置 |
| 严格校验继续发现 `windows_wsl_setup_acknowledged` 为未知字段 | 1 | 当前为 Linux 且普通模式未采用该字段；加入候选清理 |
