## 关键问题

1. 项目的端到端输入、监督、模型、输出与地图更新链是什么？
2. 雷达、激光雷达和红外在训练、推理和部署中的角色如何界定？
3. 稀疏性、噪声、时空错位、位姿误差和高速运动如何被统一建模？
4. 生成式占用预测如何与概率地图、数字高程地图及在线更新衔接？
5. 研究内容、关键技术与创新点如何形成可验证的一一对应关系？

## 决策

| 决策 | 理由 |
|---|---|
| 采用“证据约束的申报方案”组织方式 | 同时保证文本完整性、前瞻性和与仓库实际方向的一致性 |
| 最终不标注能力成熟度 | 用户明确要求不区分代码支撑与后续研究 |
| 只读审查，不运行训练 | 遵守项目规则，且当前任务不需要改变模型或生成实验结果 |
| 审查工作笔记放在独立 `.planning` 子目录 | 避免覆盖用户已修改的 `TODO/` 文件 |
| 比较“按代码模块”“按交付物”“按关键问题—系统链”三种组织方式后选择第三种 | 能让研究内容、关键技术和创新点逐项对应，并自然落到高速机载闭环 |
