# 审查结论摘要

当前项目尚未完整满足“4D Radar + 红外在线输入、LiDAR 离线监督、面向无人机局部地图与避障”的研究目标。

最准确的定位是：

> **D. 目前主要仍是模型实验，尚不具备部署路径。**

项目已经具备真实的 Radar–红外特征级融合网络、LiDAR 派生监督、单帧 Occupancy 生成和离线概率地图原型，但存在四个研究级阻塞：

1. 当前 Doppler 被固定 `50 m/s` 自运动补偿主导，不能视为有效的物理速度特征。
2. 正式推理脚本默认关闭真实红外，并指向没有红外文件的旧数据目录。
3. 训练/验证按同一场景帧级随机切分，且当前 target 被 Radar 可见性硬筛，评价存在明显泄漏和选择偏差。
4. 未建立 free/unknown 监督、连续帧位姿对齐、3D 地图更新或 ROS/规划接口，输出不能直接用于安全避障。

本次没有修改项目代码。只执行了 6 帧只读抽样、全量时间戳统计和 CPU checkpoint 元数据检查；没有训练或模型推理。项目开始时已有的脏工作树保持不变。

# 3. 每项要求详细分析

## 3.1 红外在线辅助输入

### 当前实现

代码层面确实实现了 Radar–IR 特征级融合：

1. thermal 图像由 `/thermal_cam/thermal_image/compressed` 解包：[unpack_rosbag.py:31-38](/home/zxj/catkin_ws/src/4D-Radar-Diffusion/NTU4DRadLM_pre_processing/unpack_rosbag.py:31)。
2. 预处理将灰度 thermal resize 到 `640×480`，除以 255，再复制三通道：[NTU4DRadLM_pre_processing.py:273-278](/home/zxj/catkin_ws/src/4D-Radar-Diffusion/NTU4DRadLM_pre_processing/NTU4DRadLM_pre_processing.py:273)。
3. `IR2DFeatureExtractor` 使用 ResNet18，但 `weights=None`，没有 ImageNet 预训练，也没有 RGB mean/std：[multimodal_fusion.py:64-96](/home/zxj/catkin_ws/src/4D-Radar-Diffusion/diffusion_consistency_radar/cm/multimodal_fusion.py:64)。
4. `DualModalityProjectionLayer` 将 IR 特征投影到 3D voxel frustum：[multimodal_fusion.py:194-239](/home/zxj/catkin_ws/src/4D-Radar-Diffusion/diffusion_consistency_radar/cm/multimodal_fusion.py:194)。
5. `CompleteDualModalityPerceptionNet.forward()` 对 IR 做门控后与 Radar 特征融合，最终输入 UNet：[multimodal_fusion.py:304-375](/home/zxj/catkin_ws/src/4D-Radar-Diffusion/diffusion_consistency_radar/cm/multimodal_fusion.py:304)。

因此，代码不是简单将 Radar–RGB 路径更换文件名；红外特征从结构上能够影响最终 Occupancy。

### 未满足部分

- 正式推理只有传入 `--use_multimodal_meta` 才加载真实 IR，默认关闭：[inference.py:839-846](/home/zxj/catkin_ws/src/4D-Radar-Diffusion/diffusion_consistency_radar/scripts/inference.py:839)。

- `is_mock_ir` 只增加 uncertainty，未将 IR gate 归零；合成图仍能影响结果。
- 没有过曝、模糊、低对比度或温度动态范围质量检测。

### 最小修改建议

- 将正式推理数据根改为 sensor-aware，并让真实 IR 成为多模态 checkpoint 的必需输入。
- 若 IR 缺失或质量不合格，显式令投影特征和 gate 为零，只保留 Radar。
- 解析 `calib_cam_thermal.txt` 的 K、D、原始图像尺寸，resize 后同步缩放内参并去畸变。
- 保留单通道输入，或明确记录“三通道复制”协议；增加 thermal 专用强度标准化/CLAHE 的可控配置和消融。

## 3.2 LiDAR 只能承担离线监督

### 已满足部分

模型主生成路径没有接收实时 LiDAR：

- Dataset 返回 `(target, radar, meta)`，而不是 `(lidar, radar, ir)`：[dataset_loader.py:346-412](/home/zxj/catkin_ws/src/4D-Radar-Diffusion/diffusion_consistency_radar/cm/dataset_loader.py:346)。
- LDM 前向条件是 `cond` 即 Radar、IR、R/T/K；target 只被 VAE 编码为训练 latent：[unified_train.py:1813-1872](/home/zxj/catkin_ws/src/4D-Radar-Diffusion/diffusion_consistency_radar/scripts/unified_train.py:1813)。
- `CompleteDualModalityPerceptionNet.forward()` 没有 LiDAR 参数：[multimodal_fusion.py:288-301](/home/zxj/catkin_ws/src/4D-Radar-Diffusion/diffusion_consistency_radar/cm/multimodal_fusion.py:288)。
- 逐文件 `inference.py` 仅在 `compare_with_lidar` 时读取 LiDAR：[inference.py:1207-1224](/home/zxj/catkin_ws/src/4D-Radar-Diffusion/diffusion_consistency_radar/scripts/inference.py:1207)。
- checkpoint 中没有在线 LiDAR encoder 或教师网络依赖。

所以底层 `inference.py` 可以实现：

```text
Radar + IR → 3D Occupancy
```

而不需要当前帧 LiDAR。

### 关键偏差

现有 target 不是纯 LiDAR 几何监督：

- channel 0：LiDAR occupancy。
- channel 1：LiDAR reflectivity。
- channel 2：Radar 邻域 Doppler。
- channel 3：Radar Doppler 有效 mask。

证据：[build_sensor_aware_target_vectorized()](/home/zxj/catkin_ws/src/4D-Radar-Diffusion/NTU4DRadLM_pre_processing/NTU4DRadLM_pre_processing.py:82)。

更严重的是现有数据 policy 设置 `require_radar_visibility=true`：[garden](/home/zxj/catkin_ws/src/4D-Radar-Diffusion/Data/NTU4DRadLM_Pre_sensor_aware/garden/target_policy.json:4)、[loop3](/home/zxj/catkin_ws/src/4D-Radar-Diffusion/Data/NTU4DRadLM_Pre_sensor_aware/loop3/target_policy.json:4)。LiDAR target 会先由 Radar 邻域筛选：[预处理代码](/home/zxj/catkin_ws/src/4D-Radar-Diffusion/NTU4DRadLM_pre_processing/NTU4DRadLM_pre_processing.py:66)。

6 帧抽样中，sensor-aware target 只保留旧 LiDAR target 占据数量的约 `4.1%–25.6%`。这会使评价真值偏向 Radar 已能观测的位置，夸大 Radar/模型性能，不能称为完整 LiDAR 几何教师。

此外：

- 正式 LDM/CD launcher 强制检查 target、raw Livox 和 LiDAR index，并总是开启比较：[inference_ldm.sh:58-107](/home/zxj/catkin_ws/src/4D-Radar-Diffusion/diffusion_consistency_radar/launch/inference_ldm.sh:58)。
- 因此核心 Python 可脱离 LiDAR，但正式部署入口不能。
- `--adaptive_occ_from_target` 会用当前帧 target 占据数选择预测阈值，是明确真值泄漏：[inference.py:1062-1077](/home/zxj/catkin_ws/src/4D-Radar-Diffusion/diffusion_consistency_radar/scripts/inference.py:1062)。

### 结论

```text
训练：Radar + 红外 → LiDAR几何监督
```

目前只能部分成立，因为 target 同时含 Radar 派生通道，并被 Radar 可见性筛选。

```text
部署：Radar + 红外 → 3D Occupancy
```

底层代码成立；正式 launch 和正式 checkpoint 链不成立。

### 最小修改建议

- 将监督拆成独立字段：`lidar_occupancy`、`lidar_observed/free/unknown mask`、可选 `radar_aux_target`。
- LiDAR occupancy 不再由 Radar 可见性筛选；若研究 Radar-visible 区域，应只作为额外评价 mask。
- 删除正式部署 launch 对 target/LiDAR 的强制检查，把评价参数放入独立 eval 脚本。
- 禁止正式结果使用 `adaptive_occ_from_target`，仅允许在明确标记的 oracle 上限实验中使用。

### 轻量抽样结果

- 原始 Radar col3 约 `3–25`，没有归一化为接近零。
- 原始 Doppler col4 抽样约 `-7.37–0.09 m/s`，部分帧全零。
- 体素 channel2 经补偿后均值约 `-47～-55 m/s`。
- 原因是 CLI 默认把所有帧都设为 `[50,0,0] m/s`：[NTU4DRadLM_pre_processing.py:394-397](/home/zxj/catkin_ws/src/4D-Radar-Diffusion/NTU4DRadLM_pre_processing/NTU4DRadLM_pre_processing.py:394)。
- GPS velocity 和 IMU 虽被解包，但预处理没有读取它们。
- variance 仅约 `5%–18%` 的 occupied voxel 非零，均值约 `0.0002–0.002`。

当前实现不是单纯把 Radar 当作深度点：强度、Doppler 和方差确实进入网络。但 Doppler 的物理值已被错误补偿破坏，因此不能宣称“有效利用自运动补偿后的 4D Radar 物理信息”。

### 其他物理问题

- `resize_voxel_channels()` 对 variance 只做加权插值：[dataset_loader.py:128-153](/home/zxj/catkin_ws/src/4D-Radar-Diffusion/diffusion_consistency_radar/cm/dataset_loader.py:128)。合并体素时正确公式应考虑：

```text
Var_total = E[Var_local + Mean_local?] - E[Mean_local]?
```

当前结果不是新体素的统计方差。

- PointCloud2 缺某个字段时，代码过滤 `None` 后直接保存短列，没有真正补零：[unpack_rosbag.py:75-106](/home/zxj/catkin_ws/src/4D-Radar-Diffusion/NTU4DRadLM_pre_processing/unpack_rosbag.py:75)。若仅有 velocity 而无 intensity，velocity 会落到 col3 并被当作强度。
- 几何增强若启用只旋转/翻转 Radar 和 target，不更新 IR、外参和 Doppler方向：[augmentation.py:128-158](/home/zxj/catkin_ws/src/4D-Radar-Diffusion/diffusion_consistency_radar/cm/augmentation.py:128)。当前默认关闭几何增强，因此是配置触发风险。

### 体素分辨率影响

原始体素为 `0.2m`，范围 `120×40×16m`，共 `600×200×80=9,600,000` 体素。

默认模型网格为 `(Z,X,Y)=(32,128,128)`，对应：

```text
dx=0.9375m
dy=0.3125m
dz=0.5m
```

下采样约 18.3 倍。多个细点会合并，树枝、电线和细杆难以保留；max-pool 也会改变监督体素数量和 IoU。近距 40m、Z=64 实验约为 `0.3125×0.3125×0.25m`，更合理，但不是正式默认路径。

### Free/unknown 语义错误

LiDAR target 只记录障碍物命中，没有射线 free mask。所有非命中体素都被当成 `target=0` 参与 BCE/假阳性惩罚：[vae_3d.py:589-631](/home/zxj/catkin_ws/src/4D-Radar-Diffusion/diffusion_consistency_radar/cm/vae_3d.py:589)、[unified_train.py:216-247](/home/zxj/catkin_ws/src/4D-Radar-Diffusion/diffusion_consistency_radar/scripts/unified_train.py:216)。

地图随后直接令：

```python
m_free = reliability * (1 - occupancy_probability)
```

证据：[probabilistic_mapping.py:60-69](/home/zxj/catkin_ws/src/4D-Radar-Diffusion/diffusion_consistency_radar/cm/probabilistic_mapping.py:60)。

所以“未被 LiDAR 命中”会被错误解释为空闲空间，无法安全表达遮挡后未知区域。

# 5. 当前研究定位判断

1. **当前代码是否真的实现 Radar–红外融合？**  
   架构和近期实验 checkpoint 层面是。正式默认推理路径不是。

2. **红外是否真正影响模型输出？**  
   是。前向路径和v9配对消融均证明输出会变化；但尚缺独立测试场景上的完整 real/zero/mock 结果。

3. **LiDAR是否只用于离线监督？**  
   模型前向层面是；正式 launcher 仍强制依赖 LiDAR 评价文件。target 还混入 Radar 派生通道。

4. **推理能否完全脱离LiDAR？**  
   直接调用 `inference.py` 可以；现有正式 LDM/CD launcher 不可以。

5. **Radar四个物理通道是否全部有效？**  
   四个通道都进入网络，但只有 occupancy 和强度目前数值基本可信。Doppler补偿无效，variance物理信息很弱且重采样不正确。

6. **当前输出是否可以直接用于无人机局部地图？**  
   不可以。缺少free/unknown、连续帧位姿对齐、3D地图、动态障碍和ROS接口。

7. **目前最准确的项目定位是什么？**  
   **D：多模态单帧Occupancy/点云生成实验，附带离线2D概率地图原型。**

8. **目前可以写进论文的表述：**
   - 实现了4通道Radar体素条件与thermal图像特征级融合架构。
   - IR特征经2D编码、3D投影和门控后参与Occupancy生成。
   - LiDAR派生target用于离线监督，在线模型前向不接收当前帧LiDAR。
   - 实现了VAE、LDM和EMA consistency训练实验链。
   - 在特定32帧消融中，真实IR相对zero/mock改善部分Occupancy指标。
   - 实现了单帧3D Occupancy输出和离线2D概率地图原型。

9. **目前证据不足、不能写进论文的表述：**
   - “已完成面向无人机的在线Radar–红外局部地图系统”。
   - “正式推理仅依赖4D Radar和真实红外”。
   - “实现了35–70m/s条件下准确的自运动Doppler补偿”。
   - “LiDAR提供独立、完整、无偏的几何真值”。
   - “能够表示occupied/free/unknown三态空间”。
   - “支持连续帧位姿对齐、动态障碍和地图时间稳定性”。

# 6. 修改优先级

## 第一阶段：必须立即修复

1. 改为场景/连续时间块切分，禁止相邻帧随机跨train/val。
2. 禁止正式结果使用 `adaptive_occ_from_target`。
3. 固化数据manifest，消除loop3混合预处理版本。
4. 让正式推理使用sensor-aware数据和真实IR；将评价LiDAR参数与部署入口分开。
5. 固化一套可严格加载的正式 VAE/LDM/CD checkpoint 链。

## 第二阶段：保证四项研究目标成立

1. 使用逐帧导航速度、姿态和真实时间差重算Doppler补偿。
2. 将LiDAR occupancy、可见free/unknown mask和Radar auxiliary target分开。
3. 移除Radar可见性对LiDAR target的硬筛。
4. 解析真实thermal K/D，统一训练/推理标定与同步补偿。
5. 修复RCS/Doppler归一化和variance重采样。
6. IR缺失或质量差时显式关闭IR特征，不使用mock热斑干预预测。

## 第三阶段：补充地图更新与避障接口

1. 地图更新接口增加时间戳和 `T_local_body`。
2. 先实现局部3D或分高度层Occupancy，不再只取Z轴max。
3. 对occupied/free/unknown使用一致的证据更新和时间衰减。
4. 增加动态障碍证据衰减或独立动态层。
5. 增加ROS1 publisher/service：体素地图、障碍点云、最近障碍距离、地图时间戳和坐标系。
6. 对接规划器前设置最大允许地图年龄、最小置信度和保守unknown策略。

## 第四阶段：完善实验和评价

1. 固定独立 `loop3` real/zero/mock IR消融。
2. 增加Radar通道逐项消融：Occ、+RCS、+Doppler、+variance。
3. 增加free-space、unknown、距离、高度、地面FP、细障碍和时序稳定性指标。
4. 报告完整端到端延迟：读取、预处理、IR编码、生成、后处理、地图更新和ROS发布。
5. 分别报告默认120m网格和近40m细网格，避免把VAE重建IoU写成Radar–IR端到端生成性能。

总体而言，当前最有价值的资产是“真实存在的Radar–thermal特征级融合实现”和“较完整的生成模型实验框架”；当前最需要优先解决的是数据协议、Doppler物理正确性、独立监督/评价和正式推理闭环。
